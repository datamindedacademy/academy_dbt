# Exercise 8 — Jinja: for loops

## Goal

Use a Jinja `{% for %}` loop to generate repetitive SQL columns instead of
copy-pasting them.

## Why this matters

SQL has no loops, so "one column per category" queries invite copy-paste. Every
new category means editing the query in several places — a classic source of
bugs. A for loop keeps the code **DRY** (Don't Repeat Yourself): the pattern is
written once, the categories are listed once.

## Concepts

Repetitive SQL like this:

```sql
select
  order_id,
  sum(case when payment_method = 'bank_transfer' then amount end) as bank_transfer_amount,
  sum(case when payment_method = 'credit_card' then amount end) as credit_card_amount,
  sum(case when payment_method = 'gift_card' then amount end) as gift_card_amount,
  sum(amount) as total_amount
from {{ ref('raw_payments') }}
group by 1
```

...can be generated by a loop:

```sql
select
  order_id,
  {% for payment_method in ["bank_transfer", "credit_card", "gift_card"] %}
  sum(case when payment_method = '{{ payment_method }}' then amount end) as {{ payment_method }}_amount,
  {% endfor %}
  sum(amount) as total_amount
from {{ ref('raw_payments') }}
group by 1
```

**The trailing-comma trap.** If the looped column is the *last* item in the
`SELECT`, the final iteration leaves a dangling comma — invalid SQL. Use the loop
variable `loop.last`:

```sql
{% for payment_method in payment_methods %}
sum(...) as {{ payment_method }}_amount
{% if not loop.last %},{% endif %}
{% endfor %}
```

(In the first example this isn't needed, because `total_amount` follows the loop.)

You can also assign a list to a name with
`{% set payment_methods = ["bank_transfer", "credit_card", "gift_card"] %}`, or
put the list in a dbt variable (`vars:` in `dbt_project.yml`).

## Exercise

In the `customer_stats` model, add 3 columns:

- `num_orders_with_status_o`: the number of orders of this customer with
  `o_orderstatus = 'O'`
- `num_orders_with_status_p`: same, with status `'P'`
- `num_orders_with_status_f`: same, with status `'F'`

1. Use a for loop to avoid repetition.
2. *(Optional)* Create a dbt variable `order_statuses` which lists the possible
   order statuses (`O`, `F`, `P`) and use it in the loop.

## Tips

- Count a subset with `sum(case when o_orderstatus = '...' then 1 else 0 end)`
  or `count(*) filter (where ...)` (Postgres).
- Check the rendered SQL in `target/compiled/` — it should look like the
  copy-paste version.
- Solution branch: `solutions/for_loops`.
